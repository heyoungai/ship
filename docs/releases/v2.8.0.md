# ship v2.8.0

**2026-08-03**

## Highlights

- **正式 tag push 幂等**：同一版本 push 已成功后再跑 `ship run` / `ship push`，内容未变时会跳过 push 并继续，不再因 digest 身份切片误报「拒绝覆盖」。
- **`ship ai` 顾问 v0**：可选的薄 harness（线模式 REPL / `-p`、streaming、项目沙箱工具），不替代确定性发版路径。
- **`--pull=false`**：本地已有 base 镜像时可跳过 registry 检查，减轻启动等待与镜像源 429。

## Added

- `ship ai` / `ship ai init` / `ship ai -p`：OpenAI-compatible 顾问；门禁拦截 `deploy` / `run` / `push` / `rollback`。指南：[docs/guides/ship-ai.md](https://github.com/heyoungai/ship/blob/v2.8.0/docs/guides/ship-ai.md)。
- `ship build|run --pull=false` 与 `build.docker.pull` 配置项。
- Release notes 目录：`docs/releases/`（本文件起按版本维护）。

## Changed

- `EnsureRegistryTagImmutable`：同时比较 registry pin、RepoDigests、OCI index 成员展开后的 config/layers；可证明等价则跳过 push。
- 正式 tag 冲突时的错误文案：区分「内容不一致」与「远端 index 无法完整解析」，并提示 `ship deploy -v VER -y` 或打新 tag。
- 文档分层与 quick-start / git-tag 策略补充（含「push 已成功则只 deploy」）。

## Fixed

- buildx `--load` + attestation 场景下，本地平台镜像与远端 index/list 不同 digest 切片导致的误杀重试。
- config 不同但 layers 相同不再视为等价，避免无新 layer 的 `ENV` / `ENTRYPOINT` 等变更被误放行。

## Upgrade notes

- 建议从 **≥ v2.7.1** 升级；若仍停在 v2.7.0，请先阅读 [v2.7.1](https://github.com/heyoungai/ship/blob/v2.8.0/docs/releases/v2.7.1.md) 的 digest pin 修复。
- `ship ai` 需要 `OPENAI_API_KEY`（可选 `OPENAI_BASE_URL` / `SHIP_AI_MODEL`）；未配置时主发版路径不受影响。
- 安装/更新 agent skill：`ship skill -f`（version 随二进制对齐）。

## Not in this release

以下仍在 [changes/active](https://github.com/heyoungai/ship/blob/v2.8.0/docs/changes/README.md)，**本版不含**：

- `ship run` 阶段 checkpoint / `--resume`（push 已可幂等；只差部署时继续用 `ship deploy -v VER -y`）
- `ship remote` 环境名册与线上排查命令
- 一等 `deploy.sync` / steps `root = invocation`
